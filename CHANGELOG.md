## Unreleased

- **3.3:** subagents across the platform. A new hub MCP tool `spawn_agent` lets an agent that holds a task start a helper: another agent, or one of a named vendor (so Claude can ask Codex), or the room's learned routing among everyone free except the asker. Helpers are read-only by default and run through the same path as any run (quota, capacity, the routing log with reason `subagent`, never judged or scored). `subagent_status`, `accept_subagent` and `discard_subagent` complete it. Limits (settings `subagents`: `maxDepth` 2, `budgetPerGoal` 6, `maxParallel` 3) are enforced with plain-text refusals that are audited; helper runs also count in the goal's task-run budget, and the ledger shows "Helpers: N of B started". A read-only helper gets no write tools (Claude Code write tools denied, Codex `--sandbox read-only`, and the hub's file tools refuse it). A writing helper gets its own worktree cut from the parent's current worktree (work in progress included); its changes reach the PARENT's worktree only when the parent calls `accept_subagent`, never the goal base; a clash goes back to the helper once, then the markers land in the parent's folder. Helpers are saved as tasks (`kind: "subagent"`, `parentTaskId`, `depth`, `spawnedBy`, `readOnly`), hidden from plan lists by default, and sent live as a `subagent` event; quiet room lines mark start and finish. The Mac app task panel and Activity pane show them indented under their parent with a badge, and the phone gets a Tasks sheet in the room header. Subagents an agent's own tool launches (Claude Code `Agent`/`Task` tool calls, Codex `collab_tool_call` spawn events) are recorded as `native` children for the tree and counted in the ledger, not routed, judged or budgeted. The Codex event shape is built from its source and not checked against a live Codex; the fixtures are hand-assembled, not captures.
- **4.3:** standing rooms. A room's `ROOM.md` now really governs the room. The roster limits who is planned, routed, judged, `@mentioned` (others get a short "not in this room" reply) and spawned as a subagent; judges come from outside only when a jury cannot be formed inside, and that is recorded. `tools` (`ask` or `off`) narrow each agent's permissions per room in the Claude Code and Codex arguments, MCP and the file tools; `off` denies, `ask` asks even with auto-approve. `folders` limit which grants the room's goals and file tools may use. Room memory stays in its room. New `schedule` (5-field cron), `standing_goal`, `timezone` and `catch_up_hours` start a goal as the owner ("Scheduled: ..."), skip while the last one is still running, never fire twice after a restart, catch up once after sleep within `standingCatchUpHours` (default 12) and otherwise note the miss in the digest; DST checked for America/Chicago. `GET`, `PUT` and `POST .../open` on `/rooms/:id/definition`. Mac app: a room settings pane (roster, narrowed tools, folders, schedule, next run, Edit ROOM.md, simple roster and schedule editors). Phone: a read-only room info page. Code: `packages/hub/src/rooms/`. Notes: `CONTROL.md` section 11.
- **3.4:** the office. `GET /office?roomId=` gives what each agent is doing (working, waiting for approval, idle, being judged, offline), the helpers (3.3 subagents) at each parent's desk, the goal's "Done means" list with its status and the count of pending approvals, derived from the store and the live `working` events. The hub serves `web/office.html` (three.js 0.170.0 vendored under `web/vendor/`, hash pinned in a manifest and tested): a low-poly room with a desk and an animated figure per agent in its colour, helpers as smaller figures, the whiteboard, and a door light that turns amber with a count. Click an agent to open its thread (the web app opens the DM room; the Mac app's web view and an embedding page get `{ type: "openAgent", agentId }`). It draws only while the page is visible and on screen, idle animation is about 10 frames a second, low-power mode draws on change only. On the small (8 GB) tier, without WebGL or on a phone held upright it draws the same information as a 2D plan; the owner can switch 3D/2D. Phone: an Office button in a room; Mac app: an Office screen in a web view (adds `react-native-webview`: run `pod install` once, see `docs/3.4-office.md`). Browser check: `packages/hub/test/e2e/office.e2e.mjs`. Screenshots: `docs/screenshots/3.4-*.png`.
- **3.2:** personas. Each agent's `SOUL.md` (name, colour, avatar, role, tone, bio) is editable in the Mac app (a Persona section on the agent card) and on the phone (Settings, Personas), with six starter templates (Analyst, Builder, Editor, Researcher, Operator, Skeptic). `GET` and `PUT /agents/:id/persona` and `GET /personas/templates`: a save is checked by the SOUL.md linter (its message comes back on a refusal), written as an owner commit through the control folder (or kept in the agent's record without one), and name, colour and the new avatar letter or emoji follow to every screen. The persona goes last in every prompt that makes text the owner reads (tasks, direct and tag replies, the final report, MCP assignments; Claude Code and Codex get it from their context file) between the persona markers, with "Voice only. The task, scope and rules above always win." Judges never see it: `judgePrompt` strips persona blocks from the reply and files, also when the jury is off or falls back to one judge, and `RESUME.md` never carries persona text. Code: `packages/hub/src/persona/`. Notes: `CONTROL.md` section 10.
- **2.3:** résumés and probation. The orchestrator keeps `agents/<id>/RESUME.md` from each agent's graded runs in the routing log: per task type the runs, mean quality, first-pass acceptance, send-backs, the failure-tag mix, jury agreement, the owner's spot ratings, model versions seen and the top lessons. Strengths and weaknesses are short lines that carry their numbers ("Strong on coding: 0.86 over 14 runs, 79% first-pass"; "Weak on writing: sent back 4 of 4 for verification (0.63 over 8 runs)"). Thresholds (`resume/tuning.ts`, also written at the end of every file): a type needs 3 graded runs; strong is 0.80 quality and 70% first-pass; weak is under 0.60 or half its tasks sent back; when the current model version has 3 runs of its own the line is about that version alone (2.4). The file is rewritten after graded runs at most once a minute per agent (one trailing write catches the rest) and at the end of every goal, by `orchestrator`; text under `## Owner notes` is kept; over 80% of 8 KB it is condensed (front matter never cut). The latest résumé is also kept in the database, so it works with no control folder. The planner sees each agent's strengths and weaknesses lines and who is on probation instead of the raw score table (capped per agent); RESUME.md is never put in an agent's task prompt or context file. A new agent (`POST /agents`, discovery) starts on probation; the seeded and demo agents, and agents that already have `probationRuns` (setting, default 5, 1 to 50) graded runs, do not. While on probation an agent is never the planned owner, never picked by learned routing, never offered to the planner (unless every connected agent is new: then nobody is held back). When a real task starts, each free probation agent that the capacity governor and quota admit gets a shadow copy: same prompt, own git worktree, judged like real work (jury when available), scored on its record (routing kind `shadow`, `shadow: true`), then discarded. A shadow run is never merged, adds no task, ledger line or room message (one quiet work-log line when judged), cannot ask for approval (every request is refused and audited as `shadow.denied`), post, ask another agent, save a document, propose memory or propose a file write. At the threshold probation ends with one line in the room ("Muse finished probation: 0.78 over 5 shadow tasks"), an audit entry and a fresh RESUME.md. `GET /agents/:id/resume`, `GET /resumes`, `POST /agents/:id/probation {on}` (the owner ends or restarts it, audited). Mac app: a résumé section on each agent card with progress and an End probation button. Phone: Settings, Résumés. Code: `packages/hub/src/resume/`.
- **2.2:** blind cross-vendor juries. A task's chat reply is rewritten into a neutral voice before judging (a local model does it when one is ready, else an agent from another family than the worker's; persona blocks, signatures and sign-offs are stripped first, and a rewrite that drops a number or file reference is refused for the mechanical text; files the task wrote are judged as files). Three judges from three model families, none the worker's, one of them local (quota-limited agents skipped, a local judge must be admitted by the capacity governor), grade it in parallel with the usual judge prompt; the result is one normal judgment (median score, majority verdict, per-criterion majority with ties UNSURE, merged feedback, drift when two judges flag it). With fewer than three other families ready the single rotating judge runs as before and the record says why. Every judgment is recorded in the `juries` table (`GET /juries?taskId=`) with judges, families, rewriter, Fleiss' kappa over criteria, pairwise agreement and score spread; rating a judgment records each judge's and the jury's distance from the owner's rating and keeps `jury_calibration` (`GET /jury/stats`: jury, single-judge, same-family and per-family error, the data for the "juries are worse than the user" kill criterion). A split jury emits a `jury_split` store event and an audit entry (2.7 listens). Setting `jury: { enabled, size, requireLocal, minFamilies }`; the Mac app shows a chip per judge and the agreement under each task and a switch in Settings, and goal summaries (phone too) say how the tasks were judged.

- **2.6:** slash commands from agent skills. Discovery now also indexes what each agent can run: Claude Code skills, custom commands and plugin skills and commands, Codex custom prompts and skills, Hermes skills. They show as namespaced commands (`/claude:board-deck`, `/codex:review-pr`, `/hermes:web-research`) in a `/` palette in both apps (Room commands first, then one group per agent; type to filter; up, down, Enter and Escape on the Mac, tap on the phone), from `GET /commands`. Choosing one routes straight to that agent with no planning and invokes it the way that agent supports: Claude Code commands go in as `/<name> args`, its skills as "Use the <skill> skill", Codex prompts are inlined with `$1`..`$9`, `$ARGUMENTS`, `KEY=value` and `$$` filled in, Hermes is told to run its skill. The task keeps `command` and the routing log records reason `command`. An unknown `/command` gets a short reply with close matches and never reaches an agent; room commands stay unprefixed and cannot be shadowed. The planner prompt lists each agent's best-matching commands (capped). Code: `packages/hub/src/commands/`.
- **1.1 (hub):** local file access. Folder grants can be changed (`PUT /folder-grants/:id`), checked before saving (`POST /folder-grants/check`) and filtered by room or agent; protected folders (every dot-folder under home, `~/Library`, system folders, the hub's data folder, the control folder's history) need `force` plus a written reason, audited. A goal can run on a granted folder (`folderGrantId` on `POST /rooms/:id/messages`): a git repository gets the work on a separate branch `agent-room/<goal>` and the owner's checkout is never touched; any other folder gets each task's changes back as one approval with every file's full diff (`GET /write-proposals/:id`). Read-only grants write nothing back. Claude Code and Codex runs are confined to their task worktree. Write-only grants no longer reveal whether a path exists or what it is. External MCP keys are stored as hashes, can expire, rotate and be pinned to a room (`/mcp-tokens`); a key can only be shown until the hub restarts. Every file, grant and key action is audited. Checklist for the reviewer: `docs/security/1.1-checklist.md`.
- **1.1 + 1.3 integration (apps and discovery):** Invite and Hermes auto-connect now make keys through the 1.1 key store, so a key is only ever kept as a hash. A first invite shows the key once; a second invite says it was already handed out and changes nothing (`POST /agents/:id/invite { rotate: true }` makes a new one). Hermes keeps the key already in its config while the hub accepts it, and gets a new one only when a write is about to happen. Both apps read one proposal by `approval.proposalId` (`GET /write-proposals/:id`), show a task's files with their operation, the files that won't be written and the reason a change can't be applied (only Reject then). Folder switches use `PUT /folder-grants/:id`; Add asks `POST /folder-grants/check` first and offers "Grant anyway" with a reason of 8 or more characters for protected folders. A room's composer has "Work in folder" (sends `folderGrantId`). The Mac app shows "Key hidden. Make a new key" instead of an empty key. Screenshots: `docs/screenshots/1.1-*.png`.
- **1.7:** installable app. `scripts/package-mac.sh` (one command on a Mac) builds the hub bundle, fetches official Node 22 for Apple silicon and checks its SHA-256 against nodejs.org, installs better-sqlite3 for that Node, builds the Release app, puts `Resources/node` and `Resources/Hub/` inside it, signs ad-hoc, and makes `AgentRoom-<version>.dmg` (app plus an Applications shortcut); `scripts/verify-dmg.sh` mounts it and checks structure, signature, Node, better-sqlite3 and a hub start. `HubLauncher.m` runs the bundled Node on `hub.mjs` directly (no shell) and the start-at-login agent points at them; Xcode runs still use `run.sh`. CLI sign-in happens in the app: `POST/GET /setup/signin/:agent` runs `claude auth login` / `codex login` (or `--device-auth`) headless, installs the CLI first if it's missing, returns the sign-in link or one-time code for an "Open sign-in page" button, and finishes when the CLI reports signed in; Terminal stays as a fallback. Setup timer: `setup.started` and `setup.first_goal_done` in KV, `elapsedSeconds` in `GET /setup`, shown on the welcome screen and in Settings. The README now leads with the DMG; Xcode and Setup.command moved under Develop. Test script and timing sheet: `docs/install-test.md`. Developer ID signing and notarization wait for 4.7.
- **1.2:** remote access over Tailscale. The hub reads Tailscale's state (not installed, off, needs sign-in, connected) with the tailnet IP and MagicDNS name; onboarding gets a Tailscale step and Settings a Remote access card in the Mac app, and the phone web app a read-only Remote access page. Connection snippets and the pairing address use the MagicDNS name, then the IP. Owner-switched Funnel for `/mcp` only (`POST /remote/funnel`), off by default, with drift reporting. Requests that arrive through a proxy reach `POST /mcp` and nothing else; remote `/mcp` calls are audited (`mcp.remote`) and failed auth is rate limited. Notes: `docs/1.2-remote-access.md`. Security review fixes: `POST /pair/local` needs a per-start secret from `~/.agent-room/local-pair.secret` (a local TCP forwarder no longer gets a device token), Funnel counts as on only when `/mcp` points at this hub (else drift `wrong_target`), raw TCP forwards to the hub are a warning in `GET /remote/status` and the audit log, Tailscale and `open` are found from fixed paths before PATH, remote callers can only use external MCP keys, lockouts are audited once, pairing codes use `crypto.randomInt` with a per-address failure count.
- **2.5:** memory with sources and expiry; export. Every fact carries a source (`goal`, `owner` or `agent`) and an expiry (`memoryTtlDays`: fact 90, preference 365, status 14; the keeper proposes the kind and days, `propose_memory` takes `expiresInDays` and a `source` hint). Expired facts drop out of `read_memory`, task prompts and context files, stay 30 days (`GET /memory?expired=1`), then are pruned; "Still true" (`POST /memory/:id/renew`) or a fresh assertion extends them. Existing rows migrate to `agent` with 90 days. Room and agent memory sync both ways with `MEMORY.md` (16 KB and 8 KB caps; expired first, then lowest confidence). A contradicted fact raises one question with three answers (keep old, take new, both wrong) in Approvals on Mac and phone (`POST /approvals/:id {choice}`), audited. Export of room memory into an agent's own file (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, Hermes memory file) is off by default per agent, between `agent-room:memory` markers, capped by `memoryExportBytes` (4 KB), original saved once, `GET /memory/export` for the switch text. Notes: `CONTROL.md` section 9.
