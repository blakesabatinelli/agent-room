# 3.4 The office

A visible working space: one desk per agent, helpers (subagents) at their parent's desk, the goal's "Done means" list on a whiteboard, and a light at the door for pending approvals. It is a view over the same live state as the room (PRODUCT 6.12, DECISIONS D7), not a separate system.

| Part | Files |

## What an agent's state means

Priority: waiting for approval, being judged, working, idle; a disabled agent is offline.

- Waiting for approval: it has a pending approval (raised hand, amber desk lamp).
- Being judged: one of its tasks is in review (judge's stand and gavel, violet glow).
- Working: a task is running, assigned or revising, or a `working` event is open in the room (typing).
- Helpers: tasks with `parentTaskId` (3.3) that are not finished stand at the parent task's agent's desk, smaller; a read-only one carries a magnifier. That agent's own desk is not marked busy by work it does as a helper.

## Rendering rules

- 3D when the hub says tier `medium` or `large` and WebGL works; the 2D plan (SVG, same information and clicks) on tier `small` (8 GB), without WebGL, on a phone held upright, or when the owner picks 2D. The owner's 3D/2D choice is remembered. three.js is not downloaded for the plan.
- The render loop runs only while the page is visible and the office is on screen. Idle animation is about 10 frames a second; it is drawn only when something is happening. Low power draws a frame only when something changes (and starts on if the system asks for reduced motion).
- Dark mode follows `prefers-color-scheme` and `data-theme` on the page.

## Opening an agent's thread

The page calls `openAgent(agentId)`:

1. Inside the Mac app's web view (`window.ReactNativeWebView`): `postMessage('{"type":"openAgent","agentId":...}')`; `OfficeScreen` opens the DM room.
2. Inside another page (iframe): `parent.postMessage({ type: "openAgent", agentId }, "*")`.
3. On its own (phone browser): `POST /rooms/dm/:agentId`, then `/#room=<id>`; the web app opens that room.

The device token reaches the page through `window.__AGENT_ROOM__ = { token }` (set by the Mac app's web view before the page loads) or the web app's own login in `localStorage`. It is never put in the address.

## For the owner: the Mac app needs one native step

The Mac app now depends on `react-native-webview` (13.15.0, which supports macOS). Its native part could not be built without Xcode, so after pulling this change run once on the Mac:

```
pnpm install
cd packages/app/macos && pod install
```

Then build and run as usual. If the web view cannot hold the frame rate on a Mac, D7 says to revisit (a native SceneKit view would replace only `OfficeScreen`); the 2D plan is always available from the 3D/2D switch.

## Updating three.js

`npm pack three@<version>`, copy `build/three.module.min.js` into `packages/hub/web/vendor/`, update `version` and `sha256` in `MANIFEST.json` together. The unit test fails until they agree. Use a release where `three.module.min.js` is a single file (r170 is; r171 and later split out `three.core.min.js`, which would also have to be vendored and listed).

## Running the browser check

```
node packages/hub/test/e2e/office.e2e.mjs
```

Needs Playwright (`PLAYWRIGHT_DIR`, default `/opt/node-tools`) and Chromium (`CHROMIUM`). It starts two demo hubs (large and 8 GB), checks the acceptance criteria in headless Chromium (WebGL through SwiftShader) and writes `docs/screenshots/3.4-*.png`.
