## Tailscale CLI used

Docs read on 2026-10-23:
- https://tailscale.com/docs/reference/tailscale-cli/funnel (flags `--bg`, `--https`, `--set-path`, `--yes`, `off`; `funnel status [--json]`; local proxy target must be `http://127.0.0.1`)
- https://tailscale.com/docs/reference/tailscale-cli/serve (`off` needs the original flags; `serve status --json`)
- https://tailscale.com/docs/features/tailscale-funnel (needs MagicDNS, HTTPS certificates and the `funnel` node attribute; ports 443/8443/10000; on macOS Funnel needs an open source variant of the Tailscale app)
- https://tailscale.com/docs/features/tailscale-serve (identity headers `Tailscale-User-*`; Funnel traffic carries none)
- https://tailscale.com/docs/reference/tailscale-cli (`status --json` is machine readable, format subject to change)

Commands the hub runs:

```
tailscale status --json
tailscale funnel status --json            (falls back to: tailscale serve status --json)
tailscale funnel --bg --yes --https=443 --set-path=/mcp http://127.0.0.1:<hub port>/mcp
tailscale funnel --https=443 --set-path=/mcp off
```

It never runs `reset` (that would wipe the owner's other serve settings).

Where the CLI is found (and `open`, for "Open Tailscale to sign in"): fixed absolute paths first, in this order: `$AGENT_ROOM_TAILSCALE_BIN` (must be absolute), `/Applications/Tailscale.app/Contents/MacOS/Tailscale`, `/usr/local/bin/tailscale`, `/opt/homebrew/bin/tailscale` (`open`: `/usr/bin/open`). Only if none exists is `PATH` searched, and only entries that are absolute, where neither the folder nor the file is writable by the current user (`fs.access` W_OK). The hub never hands a bare `tailscale` or `open` to the OS to look up.

## Funnel safety

1. **Only /mcp is exposed.** The Funnel handler is `--set-path=/mcp`, proxied to the hub's `/mcp`. Funnel is switched per port, not per path, so the hub refuses to turn it on if that port already serves any other path or a raw TCP forward, and reports any extra funneled path it finds (`funnel.extraPaths`).
2. **Funnel only counts as "on" when it points at this hub.** `readFunnel` is given the hub's port. A funneled `/mcp` handler counts only if it proxies to `http://127.0.0.1:<hub port>/mcp` (or `localhost`, `[::1]`). Anything else is reported as drift `wrong_target` (with the target Tailscale has), `funnel.on` stays false, and no Funnel address is put in any connection snippet.
3. **The hub checks again, best effort.** Funnel connects from 127.0.0.1, so the hub's interface check passes it. The hub treats a request as remote when it carries a proxy header (`X-Forwarded-*`, `Forwarded`, `Via`, `X-Real-IP`, `Tailscale-Funnel-Request`, `Tailscale-User-*`, `X-Agent-Room-Via` from its own relay tunnel) or arrives on loopback with a `*.ts.net` Host (any case, with or without a trailing dot, with or without a port). A remote request may reach `POST /mcp` and `GET /mcp` (405). Everything else is 404 before routing, including `/pair`, `/pair/local`, `/`, `/web/*`, `/ws`, `/remote/*` and every owner API, even with a valid device token. A remote request that carries any `Upgrade` header is 404 whatever its path. `/pair/local` and `/setup/signin` also refuse proxied requests themselves.

   **This check does not fail closed.** It is a denylist of markers a proxy normally adds. A forwarder that adds none and keeps the caller's Host off `*.ts.net` (a raw TCP forward: `tailscale funnel --tls-terminated-tcp`, `ssh -L`, `socat`) looks exactly like the Mac's own traffic, and so does a proxy whose headers were stripped on the way. So nothing that is only meant for this Mac may rely on it. That is why `/pair/local` also needs the local secret (next item), and why the hub reports TCP forwards to its own port (item 6).
4. **The Mac app proves itself with a file, not with a loopback address.** On every start the hub writes a random 256-bit secret to `<data dir>/local-pair.secret` (mode 0600, replaced atomically, so a restart rotates it). `POST /pair/local` needs it in the header `x-agent-room-local-secret` in addition to a loopback connection, a localhost Host and no Origin. The Mac app reads the file through the `HubLauncher` native module (`localPairSecret`, which refuses a file that is a link, not owned by the user, or readable by group or others) after `ensureRunning()`. A refusal is audited as `device.pair_local.denied` (at most once a minute).
5. **Every call is authenticated and audited.** `/mcp` checks the bearer token on each call. A remote caller can only use an external MCP key (the owner made it on purpose and can revoke it), never one of the orchestrator's short-lived task grants. Remote calls are audited as `mcp.remote` (agent, JSON-RPC method and tool name with control characters removed, forwarded address). Failed tokens are audited as `mcp.remote.denied`.
6. **Raw TCP forwards to the hub are a loud warning.** If Tailscale's serve config has any `TCPForward` whose target is the hub's port (`127.0.0.1`, `localhost`, `[::1]` or `0.0.0.0`), `GET /remote/status` returns it in `warnings` (and says if it is funneled to the internet), the Mac app and phone app show it in red, the start-up banner prints `WARNING:`, and it is audited once per change as `remote.tcp_forward`.
7. **Guessing is throttled.** Per forwarded address (the last X-Forwarded-For entry, which the proxy added): 10 failures, one more allowed every 6 s, then 429. The check runs before the token is read, so a locked-out caller learns nothing. The lockout is audited once, at the failure that causes it, as `mcp.remote.locked_out` (forwarded address, no token); calls refused while locked out are not audited. Local and tailnet callers are not limited.
8. **Owner intent vs Tailscale.** The owner's choice is stored (`remote_funnel`, default off). Every status read compares it with Tailscale. The comparison runs on every `GET /remote/status` (`GET /remote/status?fresh=1` re-reads the CLI first), after `POST /remote/funnel` (whether the switch worked or failed) and at start, not only at start. It reports drift (`on_in_tailscale`, `off_in_tailscale`, `wrong_target`), extra funneled paths and TCP forwards in the UI, and each problem is written to the audit log once per change (`remote.funnel.drift`, `remote.funnel.extra_paths`, `remote.tcp_forward`); a problem that goes away and comes back is audited again. It never changes Funnel on its own. Switching is audited as `remote.funnel.on` and `remote.funnel.off`.

## Pairing codes

The 6-digit code comes from `crypto.randomInt`. Wrong guesses are counted per source address (10, then 429 for that address) and the counts start again whenever the code changes (10 minutes, or after a pairing).

## Reviewer checklist

- [ ] `cd packages/hub && npx tsx --test --test-timeout=120000 test/remote.test.ts test/api.test.ts` passes.
- [ ] With the proxy-header gate commented out, the proxied-request tests fail (the tests do test it).
- [ ] On a real Mac: `tailscale funnel status --json` output matches what `readFunnel` expects (the hub reads Tailscale's ServeConfig JSON: `Web`, `Handlers`, `AllowFunnel`, `TCP`, `Foreground`). Tailscale documents the status JSON format only as "subject to change". Check that the `Proxy` value Tailscale reports for the `/mcp` handler is the exact string the hub passed (`http://127.0.0.1:<port>/mcp`); if it is normalised differently, Funnel will show as `wrong_target`.
- [ ] On a real Mac: confirm the headers Tailscale adds to proxied requests (`X-Forwarded-For`, `Tailscale-Funnel-Request`). The docs don't list them; the `*.ts.net` Host check is the backstop.
- [ ] On a real Mac, `Connection`-header probe: from outside the tailnet, with Funnel on, send `curl -i https://<name>.ts.net/mcp -H 'Connection: X-Forwarded-For, Tailscale-Funnel-Request, X-Real-IP, Forwarded, Via' -d '{}'` and then the same to `/pair/local`. A proxy that honours `Connection` as a list of hop-by-hop headers may strip the very headers the hub uses to spot it. Check in the audit log that the `/mcp` call is still recorded as `mcp.remote` and that `/pair/local` is 404. If either is not, the proxy-header gate is not enough on its own and only the Host check and the local secret are protecting the hub.
- [ ] On a real Mac: `ls -l ~/.agent-room/local-pair.secret` shows `-rw-------`, the Mac app still pairs on a fresh launch, and the secret changes after quitting and reopening the hub. Try `curl -i -X POST http://127.0.0.1:4747/pair/local -d '{}'` without the header: 403.
- [ ] On a real Mac: `tailscale serve --tcp=8443 tcp://127.0.0.1:4747` (then remove it) makes Settings > Remote access show the red WARNING and the log show `remote.tcp_forward`.
- [ ] From outside the tailnet, with Funnel on: `/mcp` with a token works; `/`, `/pair`, `/agents`, `/ws` return 404.
