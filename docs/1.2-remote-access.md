## Tailscale CLI used

Docs read on 2026-10-23:
- https://tailscale.com/docs/reference/tailscale-cli/funnel (flags `--bg`, `--https`, `--set-path`, `--yes`, `off`; `funnel status [--json]`; local proxy target must be `http://127.0.0.1`)
- https://tailscale.com/docs/reference/tailscale-cli/serve (`off` needs the original flags; `serve status --json`)
- https://tailscale.com/docs/features/tailscale-funnel (needs MagicDNS, HTTPS certificates and the `funnel` node attribute; ports 443/8443/10000; on macOS Funnel needs an open source variant of the Tailscale app)
- https://tailscale.com/docs/features/tailscale-serve (identity headers `Tailscale-User-*`; Funnel traffic carries none)
- https://tailscale.com/docs/reference/tailscale-cli (`status --json` is machine readable, format subject to change)

Commands the hub runs:

```
tailscale status --json
tailscale funnel status --json            (falls back to: tailscale serve status --json)
tailscale funnel --bg --yes --https=443 --set-path=/mcp http://127.0.0.1:<hub port>/mcp
tailscale funnel --https=443 --set-path=/mcp off
```

It never runs `reset` (that would wipe the owner's other serve settings).

## Funnel safety

1. **Only /mcp is exposed.** The Funnel handler is `--set-path=/mcp`, proxied to the hub's `/mcp`. Funnel is switched per port, not per path, so the hub refuses to turn it on if that port already serves any other path or a raw TCP forward, and reports any extra funneled path it finds (`funnel.extraPaths`).
2. **The hub enforces it again.** Funnel connects from 127.0.0.1, so the hub's interface check passes it. A request is treated as remote when it carries a proxy header (`X-Forwarded-*`, `Forwarded`, `Via`, `X-Real-IP`, `Tailscale-Funnel-Request`, `Tailscale-User-*`) or arrives on loopback with a `*.ts.net` Host. A remote request may reach `POST /mcp` and `GET /mcp` (405). Everything else is 404 before routing, including `/pair`, `/pair/local`, `/`, `/web/*`, `/ws`, `/remote/*` and every owner API, even with a valid device token. `/pair/local` and `/setup/signin` also refuse proxied requests themselves.
3. **Every call is authenticated and audited.** `/mcp` checks the bearer token on each call. Remote calls are audited as `mcp.remote` (agent, JSON-RPC method and tool name, forwarded address). Failed tokens are audited as `mcp.remote.denied`.
4. **Guessing is throttled.** Per forwarded address (the last X-Forwarded-For entry, which the proxy added): 10 failures, one more allowed every 6 s, then 429. The check runs before the token is read, so a locked-out caller learns nothing. Local and tailnet callers are not limited.
5. **Owner intent vs Tailscale.** The owner's choice is stored (`remote_funnel`, default off). At start and on every status read the hub compares it with Tailscale and reports drift (`on_in_tailscale`, `off_in_tailscale`) in the UI and the audit log (`remote.funnel.drift`). It never changes Funnel on its own. Switching is audited as `remote.funnel.on` and `remote.funnel.off`.
